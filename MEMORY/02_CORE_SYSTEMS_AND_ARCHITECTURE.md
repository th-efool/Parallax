## 1. Scene Tree & Script Architecture

### 1.1 Main Scene Hierarchy (`scenes/main/main.tscn`)
```text
Main (Node)
├── LevelRoot (Node3D)                    # Owns Entrance, Hall, Gallery, Mechanism, Execution Arena geometry & gates
├── Player (CharacterBody3D)              # scripts/player/player_controller.gd -> SpringArm3D -> Camera3D, Skeleton/Mesh, Sword Hitbox (Area3D)
├── RealmManager (Node)                   # scripts/core/realm_manager.gd (Authoritative Reality/Mirror state & safe-shift checks)
├── EncounterDirector (Node)              # scripts/core/encounter_director.gd (Linear section FSM, gates, checkpoints)
├── WorldEnvironment (WorldEnvironment)   # Warm Reality / Cool Mirror environment & light tweening
├── AllySquad (Node)                      # scripts/allies/ally_squad_manager.gd — spawns one SquadAlly per res://data/allies/*.tres
└── HUD (CanvasLayer)                     # scenes/ui/hud.tscn (Single persistent HUD across all 5 sections)
    └── RootControl/SquadCommsHUD         # scripts/ui/squad_comms_hud.gd (added by HUDController) -> owns SquadComms (plugin hub)
```
**Autoloads (`project.godot`)**:
- `RunState` (`scripts/core/score_manager.gd`): Holds score, combo chain, elapsed run timer, per-encounter no-hit flags, checkpoint banked score, and idempotent `_run_finalized` state for `finalize_run()`.
- `LeaderboardStore` (`scripts/core/leaderboard_store.gd` — or accessed statically/autoloaded): Handles `user://leaderboard.cfg` Top 5 persistence, settings, `user://savegame.cfg` state + `checkpoint_history`, and `last_save_error` disk error tracking.
- `GameAudio` (`scripts/core/audio_manager.gd`): Single authoritative `AudioManager` singleton across scene reloads (`Main/AudioManager` removed from `main.tscn`; `MainController._get_audio_manager()` binds `GameAudio` per loaded run and resets `_warden_dead`).
- `_mcp_game_helper` (`addons/godot_ai/runtime/game_helper.gd`): Already enabled for `godot-ai` MCP testing.

## 2. Physics Layers & Collision Configuration

Configured in `project.godot` under `[layer_names/3d_physics]`:

| Bit / Layer | Name | Purpose | Collides With |
| :--- | :--- | :--- | :--- |
| **Layer 1** | `Player` | Player `CharacterBody3D` | `World_Shared` + Active Realm Layer (`World_Reality` OR `World_Mirror`) + `Enemy` (active) |
| **Layer 2** | `Enemy` | Skeletons, Phantoms, Guard, Warden (active only) | `World_Shared` + Active Realm Layer + `Player` |
| **Layer 3** | `World_Shared` | Floors, walls, gates, repaired bridge, arena perimeter present in both realms | `Player`, `Enemy` |
| **Layer 4** | `World_Reality` | Reality-only walls/bridges/pillars (disabled or unmasked when in Mirror) | `Player` (in Reality), `Enemy` (in Reality) |
| **Layer 5** | `World_Mirror` | Mirror stepping stones, spectral bridge, suspended weight (disabled in Reality) | `Player` (in Mirror), `Enemy` (in Mirror) |
| **Layer 6** | `Interactable` | Mirror switch, bridge anchor, pressure plate, breakable hurtbox | Detected by Player interact `Area3D` / Sword `Area3D` |
| **Layer 7** | `Hitbox` | Sword swing / enemy strike / landing shockwave `Area3D` shapes | Opposing character hurtbox layers; never push physics bodies |
| **Layer 8** | `Player_Blocker` (`RealmManager.LAYER_PLAYER_BLOCKER`) | Invisible 2.7 m blockers above low parapets/balustrades (`GrandJourneyBuilder._parapet`) | Player (`player.tscn` mask 142) and enemies (builder adds the bit). **The camera SpringArm (mask 28 = layers 3/4/5) ignores it**, so the camera never snaps in at railings. Visible rails themselves are a separate `RailBody` on layer 3. |

> **Squad allies (2026-11-17)**: no new layer. Ally bodies use `collision_layer = 0` (nothing collides *into* them, so they never block the player or enemies) and mask the active realm's world layers + `Player_Blocker` (8). Their `Hurtbox3D` sits on layer 7 (`Hitbox`) flagged as a player-type hurtbox, so enemy `AttackHitbox`es (mask 1|7, `affects_player`) hit them while the player's sword (`affects_player = false`) and `_sweep_strike_targets` (skips player hurtboxes) never do. Ally attacks call `EnemyBase.apply_damage(..., "ally_*", ally)` directly.

> **Golden Collision Rule**: Hiding a mesh (`visible = false`) is NEVER enough for an inactive realm actor. Inactive realm geometry must disable its `CollisionShape3D.disabled = true` (or sit strictly on its dedicated `World_Reality` / `World_Mirror` layer while Player collision mask swaps). Inactive enemies must disable collision shapes, disable hitboxes, and pause `_physics_process` / AI state so they can neither deal nor receive damage.

## 3. Dimension-Shift System Rules (GDD Section 4)

### 3.1 Reality vs Mirror Ruleset Contrast
| Aspect | **Reality** | **Mirror** |
| :--- | :--- | :--- |
| **World Geometry** | Missing Entry gap; broken Gallery bridge span; solid Reality-only barriers; stone anchor housing. | Spectral stepping stones across Entry gap; complete spectral Gallery bridge; suspended Mechanism weight. |
| **Enemies** | All enemies present (2026-11-17: every archetype is `BOTH_STATEFUL`). Shielded Guard frontal shield blocks; Warden armored (Phase 1). | Same enemies, plus **insight**: `EnemyBase.evaluate_for_realm` calls `EnemyAI._on_mirror_insight(true)` → weak-point glow, damage `× mirror_damage_mult` (1.25; Warden 1.0) *(overhead `IntelTag` `E# · HP% · WEAK` and `StateIcon` labels disabled by default)*. Shielded Guard loses shield; Warden exposes chest rune during recovery (Phase 1). `ObjectiveTracker` shows a Mirror-only `MirrorInscription` hint at the current objective. |
| **Visuals & Audio** | Warm limestone, ember amber key light, sun banners, dry stone ambience. | Cold blue-black stone, cobalt rim lighting, emissive seams, moon banners, glass harmonics & filtered ambience. |

### 3.2 Exact `Q` Shift Transition Sequence (`RealmManager.request_shift()`)
1. Guard checks: Reject immediately if `shift_locked` (e.g., Warden Phase 2 merged), game paused, or `cooldown_timer > 0.0` (`0.60 s` cooldown).
2. Compute `target_realm` (toggle `REALITY` <-> `MIRROR`). **Never alter `player.global_transform`.**
3. **Safety Validation (`can_shift_to_realm(target_realm)`)**:
   - **Floor Support Check**: Raycast / shape-cast straight down (`~1.5 m`) below player's feet against `World_Shared` + destination realm's layer (`World_Reality` if shifting to Reality, `World_Mirror` if shifting to Mirror). If no valid floor exists beneath the player (except during intentional mid-air jump? -> GDD 4.3/4.5: *"Never remove the floor beneath the player during a successful shift. The destination floor-support test must reject an unsafe toggle"*), **REJECT**.
   - **Penetration / Overlap Check**: Perform `PhysicsDirectSpaceState3D.intersect_shape()` using the player's capsule shape at `player.global_transform` against destination realm layer (`World_Reality` or `World_Mirror`). If overlapping solid geometry, **REJECT**.
4. **If Rejected**: Emit `shift_rejected()`, play low rejection sound, pulse HUD realm indicator amber/red briefly. Do NOT teleport player.
   - **Finisher exception**: while `PlayerController.is_finisher_window_open()`, `RealmManager._unhandled_input` ignores `Q` — it is the Mirror Break finisher input instead.
5. **If Safe**:
   - Update `current_realm = target_realm`.
   - Start `0.60 s` cooldown.
   - Update Player collision mask (`Layer 3 | Layer 4` in Reality; `Layer 3 | Layer 5` in Mirror).
   - Call `set_realm_active()` on all registered `RealmReactive` nodes & enemies (or emit `realm_changed(target_realm)`).
   - Trigger brief `0.15–0.25 s` visual shader ripple + WorldEnvironment light/color tween + glass-harmonic SFX. **Never lock player movement/combat control during transition.**
   - Combo timer does **not** reset on realm shift.

## 4. Section State Machine, Checkpoints & Performance

### 4.1 `EncounterDirector` Linear Progression
`ENTRY` (Entry Vestibule) -> `HALL_COMBAT` (Hall of Echoes) -> `COLLAPSED_GALLERY` (Bridge + Shielded Guard) -> `MECHANISM_CHAMBER` (Landing Slam Weight Puzzle) -> `EXECUTION_ARENA` (The Warden Boss) -> `COMPLETE` (Exit Gate -> Results).
- Every gate transition, objective completion, and score award must be **idempotent** (guarded by a boolean `already_completed`) so re-entering triggers cannot double-award points or re-lock gates.

### 4.2 Checkpoint & Respawn Contract (GDD Section 11.6)
- **Checkpoints exist at**: Entrance Vestibule start, Hall of Echoes exit (upon Hall clear), Mechanism / Execution Arena entrance. *(Run state stays in memory; no save files between rooms.)*
- **On Player Death**:
  1. Show brief death overlay; respawn player at current section checkpoint transform.
  2. Restore `health = 100` (`max_health`) and reset `combo = x1`.
  3. Reset only the **current failed section's** enemies, gates, and breakables (`Cracked pillar` resets if player died in Hall).
  4. **Retain** banked score from previously completed sections; **discard** unbanked score earned during the failed section.
  5. **Run timer continues** uninterrupted (Restart Run from Pause resets everything).

### 4.3 Performance Target (GDD Section 11.7)
- Target **stable 60 FPS @ 1920x1080** on mid-range Windows PC.
- **Avoid**: Planar real-time mirror reflections (`Viewport` mirror cameras), SDFGI/VoxelGI heavy spikes, systemic physics fracturing of level geometry. Use fake specular/Fresnel shaders + environment glow instead.
- Only enemies belonging to `EncounterDirector.current_section` should be active at any time.
- **Low-end / no-dGPU support (2026-11-17)**:
  - `project.godot` `rendering_device/fallback_to_d3d12` + `fallback_to_opengl3` = true (boots on machines without working Vulkan).
  - Settings `render_scale` (0.5–1.0; FSR 1 below 1.0, applied to the root viewport in `LeaderboardStore._apply_scene_graphics_and_camera`), `adaptive_resolution` (default on), `hw_autodetected`.
  - First windowed launch: `LeaderboardStore.is_low_end_gpu()` (adapter type integrated/virtual/CPU, or name matches Intel UHD/Iris, Radeon Graphics, Vega 6/8, llvmpipe, SwiftShader, Basic Render) → Low preset. Presets set render scale: low 0.7 · medium 0.85 · high/ultra 1.0. Low also uses `mesh_lod_threshold = 4` and caps ambient creature `lod_distance` at 22 m.
  - `PerformanceGovernor` (`scripts/core/performance_governor.gd`, child of `MainController`): samples FPS every 1.5 s after a 3 s warm-up; < 45 FPS → `scaling_3d_scale −0.08` (floor 0.55); > 75 FPS → `+0.04` back up to the user's `render_scale`. Off in headless.
- **Launch flow & loading screen (2026-11-18)**: F5 → **title (main menu)** → Start / Continue → **`LoadingScreen`** (`scripts/ui/loading_screen.gd`, CanvasLayer 120, bar + `%` + step name + tips) → run begins. The level is no longer built during scene load: `GrandJourneyBuilder` / `ColosseumGreyboxBuilder` have `build_on_ready` (grand: `false`), `AmbientLifeLayout.build_on_ready = false`. `MainController._begin_run_loading()` runs `LevelRoot.build_greybox_progressive()` (one step per frame, `build_progress(fraction, label)` signal: containers, 5 stages, banners, set dressing, scenery, occluders, batching) then `AmbientLife.build_progressive()` (~85 % / 12 %), then `_wire_level_dependent()` (boss bar, interact prompts, audio world bind), then `EncounterDirector.restart_full_run()` (or `LeaderboardStore.apply_saved_world_state()` for Continue), enables the player, shows the HUD, sets `level_ready`. Until then the player node is `PROCESS_MODE_DISABLED` (no falling into an unbuilt void) and the HUD is hidden. `MainController.start_run_now()` is the test/tool entry; tests wait on `level_ready` (`_await_level()`).
- **Restart = reload (2026-11-18)**: Replay (results), Restart Run (pause) and Start/Continue after a run already exists call `MainController._reload_for_new_run()` → static `pending_auto_start` (+ `pending_continue`) then a deferred `reload_current_scene()`; the rebooted scene skips the title and goes straight to the loading screen, so enemies, gates, breakables, checkpoints and score are rebuilt from scratch (before, the director was reset but the finished world and last checkpoint stayed). Checkpoint/section restarts are unchanged. `tests/restart_flow_test.gd` verifies it.

### 5.2 Save & Load Lifecycle Hooks
- **Startup & Squad Gating**: `MainController._enter_tree()` registers `"main_controller"` before child `_ready()`, keeping `AllySquadManager` deferred until `MainController._begin_run_loading()` builds floors, restores saves/restarts run (with `auto_save_on_checkpoint` suppressed and `SectionTriggerVolume` blocked until `level_ready`), and spawns/regroups allies via `spawn_squad()`. `WeatherDirector.bind_warden()` is invoked after level build and retried in `_process()`.

### 5.3 Dynamic Control Rebinding, Validation & Live UI Sync
- **Conflict Validation (`LeaderboardStore.validate_binding(action_name, binding_code)`)**:
  - Rejects `KEY_ESCAPE` (`RESERVED KEY (PAUSE MENU)`).
  - Prevents binding any key or mouse button already assigned to another gameplay action, returning `{"valid": false, "conflict_action": other_act, "reason": "CONFLICT: <KEY> IS ALREADY BOUND TO <ACTION>"}` and emitting `rebind_rejected`.
  - Allows the intentional contextual pair `["jump", "dodge"]` to share `Space` (since `PlayerController` disambiguates `Space` contextually between gap/step jump and directional dodge).
- **Live Indicator Synchronization**:
  - Whenever `rebind_action()` or `reset_keybindings_to_default()` runs, `LeaderboardStore` updates Godot's `InputMap` immediately, saves `user://settings.cfg`, and emits `controls_rebound(action_name, display_label, all_labels)`.
  - `HUDController` listens to `controls_rebound` and `settings_changed`, immediately updating `ShiftKeyLabel` (`[Q]` -> `[<new>]`), `AttackPrompt` (`<LMB> ATTACK | <RMB> HEAVY | <DODGE> DODGE`), `LandingPrompt` (`<F> LAND`), `InteractPrompt` (`<E>: <Verb>`), and `get_tutorial_prompt_text()`.
  - `InteractSwitch` listens to `controls_rebound` and formats its world prompt via `get_formatted_prompt_text()` (`<InteractKey>: Interact`), re-emitting `prompt_changed` immediately if the player is standing in the switch zone.
